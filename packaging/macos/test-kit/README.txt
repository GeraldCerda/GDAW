GDAW Mac Test Kit v11 — source candidate

Repository: https://github.com/GeraldCerda/GDAW
Exact package revision: SOURCE_COMMIT beside this file.

The update ZIP includes the full source at source/GDAW-<SOURCE_COMMIT>, plus the matching build and launch scripts. The source files match that Git revision. It does not reuse an older source pin. The script downloads source only if that exact source directory is missing. Rust and Cargo dependencies may require downloads.

Build, install and launch:
bash "$HOME/Downloads/GDAW_Test_Kit/build_test.sh"

The normal command runs no regression suites. It builds the native Mac application, signs it locally, installs GDAW Test.app into /Applications, reveals it in Finder and launches it. macOS may request your administrator password. A previous tester in /Applications is preserved as a timestamped backup. Existing kit logs, preferences and Cargo caches remain available.

The installed app records the exact source revision as GDAWBuildCommit in Contents/Info.plist. Preferences use ~/Library/Application Support/GDAW Test. Build and launch logs use this kit's logs directory.

Source changes in this candidate:
- Uses Neon Chrome G in Futuristic Studio.png, provided through the repository, as embedded startup artwork. Its aspect ratio is preserved and it is independent of the launch directory. Startup now paints before plugin-cache restoration, plugin discovery, audio-device initialization and requested session loading. The editor waits for discovery to finish, including changed installations. Manual rescans use the same splash.
- Live scan rows report Audio Units, VST3 and CLAP separately, with current component/bundle names, completed/total counts, cached descriptors and skipped failures. The bar is indeterminate until inventories are known, then reflects completed work. Audio Units count system component registrations; they are not instantiated to prove authorization. Device opening and session/media loading still use their existing synchronous calls; their stage label is painted beforehand, but the UI can pause during those calls.
- Bottom Device View now presents a horizontal chain of bounded device blocks with activators, draggable/foldable title bars, inline parameter controls and full-editor access. Drop targets between blocks insert without overwriting neighboring devices. Cross-track gap drops insert rather than swap; ordinary explicit slot drops retain swap behavior. New browser-device gap insertion is one undo operation. Parameters, automation and plugin bus assignments follow shifted devices.
- The selected track's same device chain is available below both Edit and Mix; Pro Tools-style insert slots remain in the Edit headers and mixer strips. Empty chain/pad targets replace Add Effect buttons. Built-in parameters expose up to nine inline controls; all other controls remain available through the device window. The processing model still has ten insert positions and one instrument per instrument track; this is not an unlimited Live chain or a MIDI-effects implementation.
- Default appearance is neutral dark grey with brighter text, clearer slot edges and lower-glare surfaces. Existing appearance revisions migrate once; subsequent Dark/Light/System choices remain available. The uploaded splash keeps its purple artwork.
- Added unexecuted regression source for insertion/undo, cross-track gap drops, copy target reporting and scan progress; updated appearance expectations. Reference behavior: https://www.ableton.com/en/live-manual/12/working-with-instruments-and-effects/
- Fixes the developer-panel Context borrow error reported in build-20261017-110107.log. That log contains one Rust compiler diagnostic (E0308); compilation stopped before installation. This revision has not been rebuilt here.
- Drag plugins from the browser onto inserts, track headers and empty track space. Drag existing insert cells or device titles to reorder within a track or swap between tracks. Option-drag copies into an empty slot. Plugin state, parameter automation and plugin bus assignments move together. Instrument tracks still hold one instrument. Moving a hosted device recreates its affected instances; uninterrupted audio during moves is not established.
- Add up to 64 sample-library locations, search a background index, keep favorites and recent imports, drag samples into tracks or the timeline, and audition without moving the song playhead. Preview has its own gain, background decoding and Stop control. It reads at most 128 MiB per source, decodes up to 30 seconds with a sample bound, and does not tempo-warp. Indexing caps are 100,000 samples, 500,000 visited entries and 24 directory levels; descendant symlinks are skipped. Use Refresh for changes made while GDAW is open.
- Persistent platform-specific plugin catalogs now restore the host registries as well as the picker. Unchanged installations skip plugin enumeration on later starts. Changed installations refresh in the background using descriptor caches; Rescan Plugins explicitly refreshes everything. First discovery retains the progress screen. Cache paths honor SOUNDCRAFT_CONFIG_DIR; an empty value disables caching.
- Reported third-party instantiation failures are hidden from normal plugin pickers, with persistent reasons and Retry controls. Manual Hide handles plugins that continue loading in demo mode or defer authorization. Scan failures are listed and can be retried separately. There is no universal iLok license-status check; existing session inserts and states remain intact.
- New native sessions use .gdaw, with the existing versioned JSON schema and media folder. Legacy .scraft/.scraftz files remain readable. Portable .gdawz audio projects package the session and float WAV media, refuse missing media/video, and are limited to 1 GiB / 10,000 entries. A portable-project save/open cannot silently reuse unrelated media beside the archive.
- Export WAV Tracks and MIDI writes aligned 24-bit track WAVs, a main reference mix, Standard MIDI, session information and a JSON manifest into a new folder. Desktop rendering has progress/cancel, a captured session snapshot and staging cleanup on normal errors/cancellation. WAV origins and MIDI origins are recorded separately. Main master processing and send returns are represented in the reference mix; individual track files are not a lossless reconstruction of arbitrary bus routing. Process crashes can leave staging folders.
- Help > Developer API documents opt-in local control, capability discovery, session JSON, sample search/preview and plugin availability operations. examples/gdaw_client.py supplies a standard-library client. Command batches are ordered, not atomic. Existing CLI and MCP entry points remain available. PTX, ALS, AAF and OMF interchange are not implemented.
- Routing validation now also checks feedback cycles introduced by plugin key-input and additional-output assignments.

This includes the preceding source work for startup discovery, native plugin editors, instruments in ordinary inserts, hardware/bus routing, Touch/Latch automation, capture timestamp anchors and AudioSuite transaction fragments. Those earlier changes retain their verification limits.
This revision has NOT been compiled, type/borrow checked, linted, linked, installed or launched. No new or existing Rust tests have run. The added test source is unexecuted. Static source review, TOML parsing, shell syntax checking and Git/package byte comparisons do not establish a clean application build.

Still incomplete:
- End-to-end callback allocation/lock/deadline instrumentation, remaining hosted-plugin lifecycle paths, shutdown ownership and bounded disk streaming.
- Prepared delay-capacity replenishment and continuity beyond existing capacity; native sample-offset automation delivery instead of the existing one-sample fallback; complete gesture timing and parameter overrides between UI ticks.
- Continuous timestamp-based device drift correction, loop/seek/varispeed recording alignment, converter-latency calibration, and phase-accurate compensation of additional plugin outputs and all sidechain branches.
- Master-track sidechains, plugin port layouts beyond the exposed main/first auxiliary input and supported extra outputs, and dynamic port-layout renegotiation.
- AudioSuite preview, automatic recovery discovery/replay, replacement crossfades, media ownership/garbage collection, and a permanent project location for unsaved-session transaction media. Partial selections that change length require a full clip selection. Missing original media without a pool copy cannot be recovered.
- AAX, VST2 and asynchronously instantiated AUv3 plugins are unsupported. External MIDI-device recording/routing was not implemented or validated by this update.

Untested behavior includes every new and existing Rust test; startup paint ordering, artwork rendering/scaling, cold/cached/changed plugin scans and live progress, native menus and startup failures; device-block geometry, folding, drag targets, parameter interaction, mixer/edit synchronization and grey-theme readability; drag/reorder/copy undo and plugin-state restoration; catalog invalidation, authorization recovery and failed-scan retries; sample indexing, decoding, output routing and preview lifetime; native/portable project save/open/media round trips; WAV/MIDI export, cancellation, failure handling and other-DAW import; developer client/API/MCP requests; real AU/VST3/CLAP discovery, editors, automation and plugin states; Apollo and other physical I/O, recording offsets and drift; callback deadlines and saturation; audible delay transitions, routing null/phase tests and offline parity; AudioSuite failure/crash/reopen/undo behavior; UI rendering/interaction; Mac signing, /Applications installation and launch; Windows/Linux/web builds.

Optional verification is explicit:
bash "$HOME/Downloads/GDAW_Test_Kit/build_test.sh" --verify

--verify runs DSP/model/engine/mix/playback/UI suites. --verify-ui runs UI suites only. Both disable LTO for test executables only. The application retains its normal release link settings. Neither option runs by default.
